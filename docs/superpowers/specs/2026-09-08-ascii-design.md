# ASCII — Design Specification

- **Date:** 2026-09-08
- **Status:** Approved
- **Topic:** Self-hosted ASCII art generator (web app + API + MCP server + CLI)

## 1. Purpose

A self-hosted application for generating ASCII / FIGlet text art for use in projects. It must be deployable as a Docker Compose stack at `ascii.johansen.foo`, and expose the same generation engine to three surfaces: a website, an MCP server (so AI agents can generate art smoothly), and a compiled CLI (for use in shells like `zsh`).

Inspiration and references:
- `https://ascii.today/` and `https://github.com/lokesh/ascii-today` — the original fast FIGlet title generator (Vue + figlet.js).
- `https://omarchy.org/` — terminal/CRT aesthetic, theme cycling (`T`), keyboard-first feel.
- `https://ezascii.com/blog/best-fonts-for-unicode-and-ascii-art` — display/rendering font research.
- The `echo` project (`~/Development/echo`) — the house style this project mirrors: Next.js 16, strict TypeScript, hand-rolled everything, vitest + Playwright, better-sqlite3, token+HMAC-cookie admin auth, hardened Docker.

## 2. Scope

### In scope (v1)
- Classic FIGlet generation (`.flf` fonts), pure-ASCII output.
- A curated subset of ~40–80 licensed FIGlet fonts with per-font attribution.
- User-uploadable custom `.flf` fonts (stored in DB, with their own attribution).
- Animations (three layers): engine font-morph/reveal/color-cycling, frontend CRT/glitch/typing effects, and ANSI true-color output for CLI/MCP.
- Website: generator page, fonts gallery, `/docs`, `/admin`.
- REST API.
- MCP server (remote Streamable HTTP) + stdio shim in CLI.
- Go CLI (compiled, cross-platform).
- Themes (Terminal + Catppuccin, Dracula, Nord, GitHub, Cyberpunk) with dark/light.
- i18n: English + Danish.
- Keyboard shortcuts.
- Umami analytics.
- Docker Compose deployment.

### Out of scope (later)
- Unicode "fancy text" styles (math bold / fraktur / small caps).
- Oldschool PC (Px437) block rendering + image→ASCII converter.
- Font-morph crossfade across *all* fonts (v1 morphs within a curated "related" group).

## 3. Architecture

npm-workspaces monorepo:

```
ascii/
├── package.json                 # npm workspaces
├── docker-compose.yml
├── Dockerfile                   # multi-stage, hardened (echo-style)
├── .env.example
├── Makefile                     # fonts sync + CLI cross-compile
├── data/
│   └── fonts/                   # CANONICAL: curated .flf + fonts.json manifest
├── packages/
│   └── core/                    # TS engine (figlet wrapper, registry, attribution, animation, ANSI)
├── apps/
│   ├── web/                     # Next.js 16 App Router
│   ├── mcp/                     # MCP server (thin adapter over web API)
│   └── cli/                     # Go module (go.mod), embeds fonts
├── docs/
│   └── superpowers/             # specs + plans (internal)
└── e2e/                         # Playwright
```

### Data ownership
- `data/fonts/*.flf` + `data/fonts/fonts.json` are the canonical font + attribution source.
- TS `packages/core` reads them directly at runtime/build.
- Go CLI copies them into its module via `make fonts` (CI-enforced) and embeds with `//go:embed`.
- Only the FIGlet parser is duplicated (TS `figlet` npm + a small hand-rolled Go parser); the font data and attribution manifest are single-sourced.

### DB ownership
- The `web` app owns the single SQLite DB.
- `mcp` is a thin adapter that calls the web REST API over internal HTTP (`http://web:3000/api/...`). No cross-process DB sharing.

## 4. Core engine (`packages/core`)

TypeScript, strict. Public API:
- `listFonts(): Font[]` — `{ name, sample, author, source, license, copyright }` (copyright parsed from `.flf` header comment + manifest).
- `generate(text, opts): string` — `opts = { font, width?, horizontalLayout?, verticalLayout? }` via `figlet` npm.
- `animate(text, opts): { frames: string[]; kind: 'morph' | 'reveal' | 'wave' }` — font-morph (cycle a curated related-font group), reveal/wave (per-row), and color cycling metadata.
- `toAnsi(text, palette): string` — true-color/256-color ANSI.

Font metadata (attribution) is authoritative from `fonts.json`, which is generated by a curation script that parses `.flf` headers. Every font surfaces its author/source/license across web, API, MCP, and CLI.

## 5. Web app (`apps/web`, Next.js 16)

Conventions mirror echo: App Router, strict TS, no Tailwind (custom CSS + CSS vars), `proxy.ts` for CSP/nonce, `@/*` alias, functional components, default exports, `force-dynamic` API routes.

### Pages
- `/` — live generator: text input, searchable font picker (with previews), width/layout controls, animation toggle (CRT/glitch/typing), copy + download, per-font attribution footer.
- `/fonts` — gallery; every font previewed with author/source/license/copyright.
- `/docs` — echo-style docs (RSC, hash-nav sidebar, `DocsHighlight` for syntax highlighting).
- `/admin` — stats + settings (auth-gated).

### Themes
`data-theme` attribute + CSS custom properties (echo pattern). Six palettes: **Terminal** (green-phosphor + amber-phosphor CRT variants), **Catppuccin**, **Dracula**, **Nord**, **GitHub**, **Cyberpunk**. Global light/dark toggle; dark-only themes (Dracula/Nord/Cyberpunk) get a sensible light fallback. Theme initializer inline script with CSP hash for FOUC prevention.

### i18n
Hand-rolled typed dictionaries `messages/en.ts` + `messages/da.ts`, locale context/provider, default `Accept-Language`, cookie/localStorage override, no URL prefixes. `/admin` settings expose ISO date format + 24h clock (persisted in DB).

### Keyboard shortcuts
Global hotkey layer: `T` cycle theme, `D` toggle dark/light, `L` language, `C` copy, `/` focus input, `G` → docs, `A` → admin, `?` shortcut overlay, `Esc` close modals.

### Umami
Echo-style `<script>` tag gated on `UMAMI_SCRIPT_URL` + `UMAMI_WEBSITE_ID`, whitelisted in CSP.

## 6. API (echo conventions)

Stable error shape `{ error, code }`, `force-dynamic`, rate limiting with `x-ratelimit-*` headers, structured JSON logging.

- `GET /api/health`
- `GET /api/fonts`, `GET /api/fonts/:name`
- `POST /api/generate`, `POST /api/animate`
- `POST /api/fonts` (admin, upload `.flf` + attribution)
- `GET /api/settings`, `PUT /api/settings` (admin)
- `GET /api/stats` (admin)
- `POST /api/admin/login`, `POST /api/admin/logout`, `GET /api/admin/session`

## 7. Database (better-sqlite3, `schema.sql`)

- `generations(id, ts, source [web|api|mcp|cli], font, width, ok, text_hash)` — historical stats, retention-pruned.
- `settings(key, value)` — date format, clock, theme, locale, rate limits.
- `fonts(id, name, content, author, source, license, created_at)` — user-uploaded.
- Admin session revocation map (echo pattern), WAL mode.

## 8. MCP server (`apps/mcp`)

`@modelcontextprotocol/sdk`, Streamable HTTP transport. Tools:
- `generate_ascii(text, font, width, color)` → ASCII/ANSI
- `list_fonts`
- `preview_font(font, text)`
- `animate(text, font)`

Each tool calls the web API internally; stats attributed to `source=mcp`. CLI ships a stdio shim for local/offline use.

## 9. CLI (`apps/cli`, Go)

`ascii "hello"` with flags: `--font/-f`, `--list`, `--preview`, `--width`, `--layout`, `--animate`, `--color/--no-color`, `--remote <url>`. Embedded curated fonts (local engine) by default; `--remote` hits the API. Cross-compiles macOS amd64+arm64, Linux amd64+arm64, Windows amd64 via Makefile + CI matrix. `zsh` function documented for prompt banners.

## 10. Deployment

Two services in `docker-compose.yml`:
- `web` — Next.js (standalone output), owns DB volume, internal `:3000`.
- `mcp` — Node MCP server, internal `:3200`.

One `ascii-data` volume. Hardened like echo (`read_only`, `tmpfs /tmp`, `cap_drop: [ALL]`, `no-new-privileges`, `pids_limit`). Reverse proxy is **nginx-proxy-manager**: `/` → `web:3000`, `/mcp` → `mcp:3200`, TLS at `ascii.johansen.foo`. App trusts `X-Forwarded-For` for rate limiting. Umami remains an external script tag. CI builds multi-arch image (GHCR) + CLI binaries.

## 11. Testing

- Vitest (core + web + api), echo's coverage thresholds (statements/lines/functions 80%, branches 70%).
- Playwright e2e in `e2e/`.
- Go `go test` for the CLI FIGlet parser.
- Tests co-located (`*.test.ts` / `*.test.tsx`).

## 12. Build order (phases)

0. Scaffold (workspaces, docker, CI, `make fonts`, lint/test config).
1. Core engine + curated font set + attribution manifest.
2. Web skeleton (layout, themes, i18n, umami, hotkeys, CSP).
3. Generator + fonts pages + animations UI.
4. API + DB (schema, stats, settings, uploads, admin auth).
5. Docs + Admin pages.
6. MCP server + stdio shim.
7. Go CLI + cross-compile.
8. Compose + nginx-proxy-manager README + e2e polish.

Vertical slice lands at Phase 3 (generate art on the web).
